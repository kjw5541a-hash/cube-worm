# 큐브 지렁이 — 게임 방식 선택(기존 / 타임어택)과 최고 기록 설계

2026-10-16. 기존 스펙(`2026-10-06-cube-worm-design.md`)의 1절 "최고 기록"과 2절 "화면 흐름"을 구체화한다. 둘이 어긋나면 이 문서가 맞다
(기존 스펙의 저장 경로 `user://save.cfg` 는 실제로는 `user://cube_worm_save.cfg` 다).

2026-10-18 변경(사용자 요청, 브랜치 `time-attack-random`): 타임어택 배치를 고정 시드 한 판에서 **시도마다 무작위**로 바꿨다.
아래 2·4·5·6·8절을 그에 맞게 고쳤다.

## 목표

- 시작 그림을 터치하면 **방식 선택** 화면이 나온다: ① 기존 방식(레벨 진행, 점수) ② 타임어택(레벨 8 판의 벌레를 전부 먹는 데 걸린 시간. 판은 시도마다 무작위).
- 방식마다 **최고 기록**(점수 / 시간)을 기기에 저장하고, 앱을 업데이트(재배포)해도 지워지지 않게 한다. 기록이 보이면 다시 도전하고 싶어진다.
- 규칙 코드(`Game`)는 화면·저장·방식을 모른다. 방식 구분은 `Main` 이 한다.

사용자가 정한 것: 방식 선택 화면, 두 방식, 타임어택은 "전체 벌레를 먹는 데 걸린 시간", 기록은 업데이트해도 유지,
타임어택 판은 **레벨 8 한 판**(레벨 선택·이어달리기는 하지 않는다. 배치는 2026-10-18 부터 시도마다 무작위). 나머지는 채팅에서 설계를 보여 주고 승인받았다.

## 1. 화면 흐름

```
시작 그림(TAP) ──터치──▶ 방식 선택(MENU) ──버튼──▶ 판(WAITING → RUNNING → DEAD / CLEARED)
                              ▲                          │
                              └──── HUD "메뉴" 버튼 ─────┘
```

- `Title` 은 두 상태를 가진다. **TAP**: 그림 한 장(지금과 같다). 터치하면 BGM 을 시작하고(지금과 같다) **MENU** 로 간다.
- **MENU**: 같은 그림 위에, 그림 아래쪽의 "TAP TO START" 글자를 어두운 띠로 덮고 그 위에 버튼 둘을 세로로 놓는다.
  버튼마다 제목과 한 줄 기록이 있다.
  - `기존 방식` / `최고 점수 128` (없으면 `기록 없음`)
  - `타임어택` / `최고 기록 42.31초` (없으면 `기록 없음`)
- 버튼을 누르면 `start` 소리가 나고, 그 방식의 **새 판**이 준비된다(WAITING. 지렁이 선택 줄 등은 지금과 같다).
- HUD 왼쪽 위(점수·타이머 아래)에 작은 `메뉴` 버튼이 있다. 누르면 바로 MENU 로 돌아간다(확인창 없음. 기록은 이미 저장돼 있다).
  MENU 를 거치면 같은 방식을 다시 골라도 항상 새 판이다.
- MENU 가 떠 있는 동안 게임은 진행하지 않고(`game.advance` 를 부르지 않는다) 입력도 게임에 닿지 않는다.
- MENU 로 올 때마다 최고 기록을 저장소에서 다시 읽어 버튼에 보인다.

## 2. 타임어택 규칙

- **판:** `Game.new(randi(), false, Tuning.TIME_LEVEL)`. `TIME_LEVEL` = 8(8층, 벌레 9마리 = 종류마다 3, 바위 8개).
  시도마다(방식을 고를 때, 죽은 뒤, 클리어 뒤) 바위·벌레를 새로 무작위로 놓는다. 그래서 시간 기록에는 판 운이 섞인다.
  지렁이 시작 상태와 속도 규칙(벌레를 먹을수록 빨라짐)은 기존과 같다.
- **깰 수 있는 판인가:** 다시 뽑는 규칙은 두지 않는다. 2026-10-18 에 시드 1~3000 으로 판을 만들어 보니 모든 판에서 모든 벌레가
  바위를 거치지 않고 머리 칸에서 닿았고, 막다른 칸(열린 이웃이 하나 이하)의 벌레가 둘 이상인 판도 없었다(하나면 마지막에 먹으면 된다).
  벌레가 5개 미만의 층에 몰린 판은 약 10%(290판)였다.
- **타이머 `Game.elapsed`(초):** 상태가 `RUNNING` 이고 `paused`(맵 회전 중)가 아닌 프레임의 `delta` 를 더한다.
  그래서 첫 방향 입력부터 세기 시작하고, 마지막 벌레를 먹으면(`CLEARED`) 멈추고, 죽어도(`DEAD`) 멈추고, 맵을 도는 동안(`TURN_TIME`)도 멈춘다.
  오차는 최대 한 프레임이다. 클리어 걸음 안의 초과분 보정은 하지 않는다.
- **HUD:** 왼쪽 위 큰 글자는 타이머(실행 중 소수 첫째 자리 `12.3`, 대기 중 `0.0`), 가운데는 `타임어택` 과 작은 글자 `최고 42.31초`(없으면 `최고 --`),
  타이머 아래에 `남은 벌레 N`. 점수 라벨은 숨긴다(점수는 계산만 하고 저장·표시하지 않는다). 벌레를 먹을 때 뜨는 `+N` 은 그대로 둔다. 층 눈금 등 나머지 HUD 도 그대로다.
- **죽음:** 지금과 같다(흔들림, 소리, `탭하면 다시 시작`). 그 시도는 끝이다. 탭하면 새 배치로 새 판을 만들고 타이머는 0 이다.
  죽지 않고 다 먹은 시도만 기록이 된다.
- **클리어:** 걸린 시간 `ms = Records.to_ms(game.elapsed)` 를 저장된 최고와 비교한다(`Records.judge_time`).
  기록이 없었으면 첫 기록, 더 빠르면 신기록이고 둘 다 저장한다. 같은 밀리초는 신기록이 아니다.
  `CLEAR_DELAY`(0.8초) 뒤 결과 문구가 뜬다. 소리는 지금의 `clear` 하나뿐이다(신기록 전용 소리 없음).
  ```
  클리어!
  42.31초
  신기록!            ← 첫 기록이면 "첫 기록!", 둘 다 아니면 "최고 41.80초"
  탭하면 다시 도전
  ```
- **다음:** 탭하면 레벨 8 을 새 배치로 다시 한다. 다음 레벨로 가지 않는다.

## 3. 기존 방식

- 규칙은 하나도 바꾸지 않는다: 레벨 1부터, 죽으면 같은 레벨을 그 레벨 시작 점수로 다시, 클리어하면 다음 레벨(점수 이어짐), 레벨 8 은 반복.
- 이 방식을 고를 때마다 새 세션이다: 레벨은 시작 레벨(주소 `?level=N` 이 없으면 1), `base_score` 는 0.
- **최고 점수:** 세션 중 한 번이라도 도달한 가장 높은 점수. 죽어서 점수가 레벨 시작 값으로 돌아가도 최고는 내려가지 않는다.
- **표시:** 레벨 글자 아래에 작게 `최고 N`(없으면 `최고 --`).
- **갱신:** 벌레를 먹어 점수가 저장된 최고를 넘는 순간 최고를 갱신하고 바로 저장한다.
  시작 때 이미 기록이 있었으면(0 보다 크면) 세션에서 처음 넘는 순간 한 번 `신기록!` 을 기존 `Hud.pop`(금색)으로 화면 위쪽 가운데에 띄운다.
  기록이 없던 첫 플레이에서는 띄우지 않는다(첫 벌레부터 "신기록!" 이면 어색하다).
- **확인용 주소:** `?level=N`(N≠1)이나 `?perf` 로 시작한 판은 기록을 읽기만 하고 쓰지 않는다(점수를 부풀려 쓰는 일을 막는다).
  타임어택은 `?level`, `?perf` 를 무시한다.

## 4. 기록 저장

기존 저장 파일(`user://cube_worm_save.cfg`)의 `progress` 칸에 키 셋만 더한다. 스킨(`worm_skin`)·소리(`sound_muted`)는 그대로다.

| 키 | 형식 | 뜻 |
|---|---|---|
| `best_score` | 정수 | 기존 방식 최고 점수. 없음·1 미만·정수 아님 = 기록 없음 |
| `best_time_ms` | 정수(밀리초) | 타임어택 최고 시간. 없음·1 미만·정수 아님 = 기록 없음 |
| `best_time_layout` | 문자열 | 위 시간이 나온 판 배치 이름(지금은 `8-2`). 지금 배치와 다르면 기록 없음으로 본다 |

- 읽기: 파일이 없거나 깨졌거나 값 형식이 틀리면 기록 없음(0). 죽지 않는다(`load_skin` 과 같다). 옛 저장 파일(스킨·소리만 있는 것)도 그대로 읽는다.
- 쓰기는 읽고-고쳐-쓰는 기존 패턴이고, **좋아지는 방향으로만** 쓴다. `save_best_score(score)` 는 저장된 값보다 클 때만,
  `save_best_time_ms(ms, layout)` 는 같은 배치의 저장된 값보다 작거나 아직 없거나 저장된 배치가 다를 때만 쓰고 `true` 를 돌려준다.
  호출하는 쪽이 나쁜 값을 넘겨도 기록이 내려가지 않는다.
- 판 배치 이름 `Records.time_layout()` = `"<TIME_LEVEL>-<TIME_LAYOUT_VERSION>"`(지금 `8-2`, 고정 시드 시절은 `8-1-1`). 레벨을 바꾸거나 판 생성 규칙을 바꿔
  `TIME_LAYOUT_VERSION` 을 올리면 옛 시간은 다른 판의 기록이라 숨겨진다(파일에서 지우지는 않고, 새 기록이 나오면 덮어쓴다).
  무작위 배치로 바꾸며 버전을 2 로 올렸으므로 고정 배치에서 낸 옛 시간은 숨겨진다.
- **업데이트해도 유지되는 이유:** 기록은 배포 파일이 아니라 브라우저 저장소(`user://`)에 있어 재배포로 바뀌지 않는다.
  다만 아래를 바꾸면 사라지므로 테스트로 고정한다: 저장 파일 경로, `progress` 칸과 키 이름 셋, 프로젝트 이름(`application/config/name` = `큐브 지렁이`, 사용자 데이터 폴더가 이 이름에서 나온다).
- **판 생성 규칙이 바뀔 때:** 고정 배치 스냅샷 테스트는 무작위 배치로 바꾸며 없앴다. 판 생성 규칙을 바꾸면 `TIME_LAYOUT_VERSION` 을 올리는 일은 사람이 챙긴다.
- **한계(그대로 둔다):** 기록은 그 기기·그 앱 안에만 있다(브라우저 탭과 홈 화면 웹앱은 저장소가 따로일 수 있다).
  사이트 데이터를 지우면 기록도 지워진다. 서버·순위표·기록 내보내기·기록 지우기는 없다.
  웹에서 저장은 파일을 쓴 뒤 브라우저가 비동기로 반영하므로, 쓰자마자 탭을 닫으면 마지막 기록이 빠질 수 있다(지금 스킨 저장과 같다).

## 5. 구조

| 파일 | 변경 |
|---|---|
| `scripts/game.gd` | `var elapsed := 0.0`. `advance` 가 `RUNNING` 이고 `paused` 가 아닐 때 `delta` 를 더한다. 나머지 규칙은 그대로 |
| `scripts/records.gd` (새, `class_name Records`, 정적 함수만) | `to_ms(seconds)`, `format_time(ms, decimals)`, `judge_time(ms, best_ms)`, `judge_score(score, best)`, `time_layout()`, 열거 `Verdict { NONE, FIRST, NEW_BEST }` |
| `scripts/save_data.gd` | `load_best_score` / `save_best_score` / `load_best_time_ms(layout)` / `save_best_time_ms(ms, layout)` |
| `scripts/tuning.gd` | `TIME_LEVEL`, `TIME_LAYOUT_VERSION` |
| `scripts/title.gd` | TAP / MENU 두 상태, `enum Mode { CLASSIC, TIME_ATTACK }`, 신호 `mode_chosen(mode)`, `set_records(best_score, best_time_ms)`, `show_menu()` |
| `scripts/hud.gd` | 타이머·`최고`·`남은 벌레` 글자, `메뉴` 버튼(신호 `menu_pressed`), 방식별 표시 전환 `set_mode(mode)` |
| `scripts/main.gd` | `mode`, 최고 기록 값, `start_mode(mode)`, 방식별 새 판·죽음·클리어·다음 처리, 메뉴 처리, MENU 중 게임 정지 |

흐름: `Title.mode_chosen` → `Main.start_mode`(세션 초기화 + 새 판). `Game.ate` → (기존 방식) 점수 비교·저장·`신기록!`.
`Game.cleared` → (타임어택) 시간 판정·저장·결과 문구. `Hud.menu_pressed` → `Main` 이 기록을 다시 읽어 `Title.set_records` → `Title.show_menu`.

## 7. 만드는 순서

1. `Records` + `SaveData` 기록(호환·이름 고정 테스트 포함).
2. `Game.elapsed` + 타임어택 판 배치(시드 고르기, 스냅샷 테스트. 2026-10-18 무작위 배치로 바꾸며 둘 다 없앴다).

4. `Hud` 표시(타이머·남은 벌레·최고·메뉴 버튼).
5. `Main` 연결과 흐름 테스트.
6. 브랜치 푸시(Pages 배포) → 웹에서 확인 → 폰에서 확인.

## 8. 확인할 것

**웹 확인(자동 조작):** 선택 화면, 두 방식 시작, 타임어택 타이머, 죽음 뒤 재도전. 저장은 기록을 쓴 뒤 새로고침해도 남는지, 재배포 뒤에도 남는지를 저장소의 파일을 읽어 확인한다.
클리어·신기록 화면은 자동 조작으로 끝까지 가기 어려워 흐름 테스트로 확인하고, 실제 화면은 폰에서 본다.

**플레이로 판단할 것:**
- 레벨 8 판이 타임어택으로 적당한지(너무 어렵거나 길지 않은지). `TIME_LEVEL` 한 줄로 바꿀 수 있고, 바꾸면 옛 시간은 자동으로 숨겨진다.
- 판마다 걸리는 시간 차이(판 운)가 너무 크지 않은지.
- 타이머와 `남은 벌레` 글자가 잘 보이는지, 방식 선택 화면 모양.
- `메뉴` 버튼이 실수로 눌리지 않는지(필요하면 확인창을 넣는다).
